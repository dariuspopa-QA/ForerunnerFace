# APEX — round Garmin watch face

Connect IQ watch face (Monkey C) designed on the Garmin Forerunner 970 (`fr970`, 454 × 454 round
AMOLED) and shipped to every round watch with Connect IQ API 5.0+ (66 products, 218–466 px, AMOLED
and MIP; see "Other watches" below).
The project was generated by "Monkey C: New Project → Watch Face"; the template's placeholder
settings (`BackgroundColor`, `ForegroundColor`, `UseMilitaryFormat`) and the `TimeLabel` layout are
to be replaced by what this file describes.

Design source: `design/Face.dc.html` is the reference implementation of the face (HTML/SVG, drawn at
native 454 px, so every coordinate below maps 1:1 to the watch). `design/Main.dc.html` shows the
settings UI, `design/States.dc.html` the three display modes, `design/Anatomy.dc.html` the parts.
Those files are a mockup format, not code to port literally — read them for geometry and colours.
Live canvas: https://claude.ai/artifact/7gsMZx2RaPwpc2yYd2UVtC

## Concept

Pure black ground, near-white ink, ONE accent colour. Huge time: hours in Roboto Condensed Bold,
minutes in Roboto Condensed Regular — weight, not colour, separates them. (The design and 1.0.1–1.0.3
used Barlow Condensed 800 / 200; from 1.0.4 the face is set in Roboto as the 1.0.0 build looked on
the watch, at the user's request: the ExtraBold hours were too heavy.)
A 270° arc (default Body Battery) wraps the face with its number in the gap at 6 o'clock. A single
accent tick sweeps the rim for seconds. Three small data fields under the time. Nothing else.

## Geometry (454 × 454, centre cx = cy = 227)

All angles below are clock angles (0° = 12 o'clock, clockwise) unless marked "CIQ".
Connect IQ `dc.drawArc` uses CIQ degrees: 0° = 3 o'clock, counter-clockwise positive.
Call `dc.setAntiAlias(true)` before drawing.

| Element | Spec |
|---|---|
| Minor ticks | 60 ticks, radius 216 → 222 (centred r 219), length 6, width 1.4, colour `minor` |
| Major ticks | every 5 min (12 ticks), radius 213 → 225, width 3, colour `major` |
| Seconds trail | circle r 226, width 1, accent at 55 % visual weight (blend accent 55 % over black), from 12 o'clock clockwise to the current second. Active mode only |
| Seconds comet | line from r 224 → r 202 (y 3 → 25 at 12 o'clock), width 4, round caps, accent, rotated to `sec × 6°`. Active mode only |
| Arc track | r 198, width 4, colour `rule`, 270° from clock 225° (bottom-left) clockwise to clock 135° (bottom-right). In CIQ degrees: from 225° clockwise to 315° (`Graphics.ARC_CLOCKWISE`, 225 → −45) |
| Arc fill | same arc, accent, round caps, length = 270° × pct, starting at the bottom-left end |
| Date | weekday + date by the `DateFormat` setting: `MON 28-09-2026` / `MON 09-28-2026` (day and month padded), or `MON 28 SEP` (day without padding, month; upper case), Roboto Regular 26 px (enlarged from the design's 13 px, then from 22 px in 1.0.4), letter-spacing ≈ 2 px, colour `dim`, centred at y ≈ 94 |
| Hours | Roboto Condensed Bold 156 px (same digit height as Barlow at 164 px; 176 px in a 1.0.4 test build was too big), colour `numerals`, right-aligned to x = 222 (x = 214 with the colon), digits vertically centred at y ≈ 196 (digit height ≈ 115 px), follows the watch's `DeviceSettings.is24Hour`: zero-padded 24 h, or 1–12 unpadded in 12 h (no AM/PM marker; Sunrise / Sunset fields too) |
| Minutes | same size, Roboto Condensed Regular, colour `numerals` (AOD: Roboto Condensed Light, `dim`), left-aligned from x = 232 (x = 240 with the colon) |
| Colon | optional (`TimeColon` phone setting or the editor's "APEX with colon" style, off by default): minutes' font and colour, centred at x = 228 (1 px away from the heavier hours), centred on the digits by the font generator |
| Separator | 60 × 1 px line, x 197 → 257, y 280, colour `rule` |
| Data fields | row centred on x = 227; up to 3 columns, 36 px gap; each column centred: label Roboto Regular 18 px (letter-spacing ≈ 2 px; enlarged from the design's 10 px for legibility, 16 px before 1.0.4) colour `dim` centred at y ≈ 302, value Roboto Condensed Bold 34 px (28 px before 1.0.4) colour `ink` centred at y ≈ 334. Empty slots are skipped and the row re-centres. Measure widths with `dc.getTextWidthInPixels` |
| Arc readout | value Roboto Condensed Bold 32 px (26 px before 1.0.4), accent, centred at (227, 386); label Roboto Regular 16 px (letter-spacing ≈ 2 px; enlarged from 9 px, 14 px before 1.0.4) `dim`, centred at (227, 412) |

Use `dc.getWidth()` / 454 as a scale factor so the layout survives other resolutions.

The time has ~2 px to spare at the arc on the 218 px watch with the colon (Roboto Condensed is
wider than Barlow, hence 156 px).
`ApexDeviceTest` checks the date, the time (with and without colon, at its top corners) and
the longest arc label against the arc and ticks on every screen size.

### Other watches

Products are all round watch-face devices on API 5.0+ (rectangular Venu Sq / X1 and the
semi-octagon, monochrome Instinct screens are deliberately out). `tests\check-resources.ps1` checks
every product is round. On those watches:

- **Fonts per screen size**: the bitmap fonts live in `resources-round-<W>x<W>/fonts/` (9 sizes,
  see Fonts). A device override in `monkey.jungle` drops these automatic folders, so every
  override line must list its own `resources-round-<W>x<W>` (the resource check enforces it).
- **No scalable fonts** (all MIP watches, and some AMOLED ones such as the Venu 2 family):
  `Graphics.getVectorFont` is missing, so it is guarded with `has`. It is only a fallback now (if the
  bitmap fonts can't load), after which the system font closest to the design size is used
  (`ApexLayout.pickFont`). Text rows are laid out from real font heights
  (`ApexLayout.rowExtent` / `rowBelow` / `rowAbove`) so nothing overlaps.
- **Pen widths** below 1 px throw on small screens: always go through `ApexLayout.penWidth`.
- **MIP colours**: 64-colour palette (channels 00/55/AA/FF). Greys darker than ~0x2B round to black,
  so the minor ticks and rule use `0x555555` there, `0x550000` at night (`ApexLayout.palette`).
- **MIP low power**: no burn-in protection, so the normal face stays on, and `onPartialUpdate`
  redraws the seconds comet + trail once a second, clipped to the box around the old and new comet
  (`ApexLayout.cometBox`) to stay inside the power budget.
- **The on-device editor**: `editor-full/configs/watchface.xml`, or `editor-basic` (no Sleep score)
  for the watches whose firmware lacks `COMPLICATION_TYPE_SLEEP_SCORE` (listed in `monkey.jungle`;
  the resource check verifies every product's types against its device API).
- Check layout changes on every screen size in the simulator (fr255s 218, fenix7s 240, fenix7 260,
  enduro3 280, venu2s 360, fr165 390, fr265 416, fr970 454, fenix9pro51mm 466 px; see
  `store/tools/README.md`), and run the unit tests on a MIP device (fenix7) as well as on the fr970.

The display may quantise to fewer colours; pick the nearest if a value renders visibly off.

## Display modes

1. **Active** (wrist raised, high power): everything above, redraw every second.
2. **Always-On** (`onEnterSleep`, and `System.getDeviceSettings().requiresBurnInProtection` is true):
   only date, hours (thin), minutes (dim), and the 12 major ticks in `0x4A4A46` (inset 10 px).
   No seconds, no arc, no fields, no readout. Garmin's AMOLED rules: at most 10 % of pixels lit per
   update, and (older models) no pixel lit for more than 3 minutes. Everything moves by
   `FaceKit.AOD_SHIFTS` (shared core, `FaceCore/kit`), which spreads ≥ 14 px across and down over any 4 minutes (hour
   strokes are ~12 px wide). Measure with `tools\aod-burnin.ps1` on 8 consecutive Always-On frames:
   currently ~5.6 % lit, and 16 pixels (where successive minute digits overlap by chance) stay lit
   4–5 minutes. The pattern was searched with `tools\aod-optimize.ps1` (offline render of minutes
   00–59: ~37 px per hour over the limit, down from 275); a residual this small can't be ruled out
   for every minute sequence. `onExitSleep` returns to Active.
3. **Night (Red Shift)**: the red palette above, via the `NightMode` setting: Off / Auto
   (`UserProfile.getProfile()` sleep and wake times) / On. The fr970's system Red Shift does tint
   third-party faces (luminance-based, no API to detect it), but most of the 66 watches have no Red
   Shift, so the setting exists for them. In Always-On at night the major ticks are `0x5C1E18`.

## Settings (replace the template's)

Expose these in `resources/settings/properties.xml` + `settings.xml` (list settings) with strings in
`strings.xml`, and read them with `Application.Properties.getValue`. `onSettingsChanged` already
calls `WatchUi.requestUpdate()`.

- `Field1` (default Heart rate), `Field2` (default Steps), `Field3` (default Sunset): number enum below
- `Arc` (default Body Battery): number enum below
- `AccentColor`, `NumeralColor`: list of the colours above (numerals has an "Accent" entry — use a sentinel like `-1`)
- `InkColor`, `DimColor`: optional, defaults `0xF4F4EF` / `0xB0B0AA`
- `NightMode`: 0 Off (default), 1 Auto, 2 On (see Display modes)
- `DateFormat`: 0 Watch (default), 1 `MON 28 SEP`, 2 DD-MM-YYYY, 3 MM-DD-YYYY (weekday kept in front).
  Connect IQ doesn't expose the watch's date order, so Watch infers it from `distanceUnits`
  (statute → MM-DD-YYYY, metric → DD-MM-YYYY), re-read each minute. There is no time-format
  setting on purpose: the time always follows the watch's 12 / 24 h setting
- `TimeColon` (boolean, default false): a colon between hours and minutes. The editor's style sets it
  too; whichever side changed last wins (`FaceEditor.pick`)

Accent and numeral lists were extended beyond the design's five/four colours (Amber, Mint, Cobalt,
Violet, Scarlet; numerals also Silver and every accent hue) so the user has a range to pick from.
`READY` / `READINESS` are hidden: the fr970 publishes no Training Readiness complication.

### On-device editor (Garmin's native watch face editor, API 5.1+)

The user must be able to change data and colours on the watch itself. `editor-full/configs/watchface.xml`
(and `editor-basic`, the same without Sleep score; see Other watches) declares it; `source/ApexEditor.mc` holds the delegate; the view applies the editor's choices on top of
the phone settings (editor wins when it has a value).

- Data slots 1–3 = the fields (left → right), an explicit list of system data types; types the face has its own source for map to
  the metric table, any other system data field is shown via `Complications.getComplication`
- Data slot 4 = the arc (Body Battery, Steps → step goal, Battery, Stress, Intensity minutes)
- Style 1 "APEX" (default) / style 2 "APEX with colon" (`ApexEditor.STYLE_COLON`)
- Accent colour = accent; Data colour = numerals (time digits)
- While a slot is being edited the editor draws it (`drawSlot`) right after each scroll, before the
  face's next `onUpdate`, and asks for its drawable (`getComplicationDrawable`) before it reports the
  edit: the face takes the new type from that `ComplicationRef` and lays the fields out again in
  `drawSlot`, or it shows the previous choice
- The editor zooms the selected slot in and out around the centre of its box (`editorSlotBox`), so
  `drawSlot` draws a field centred on that box, not at its layout position (otherwise the zoom
  throws the left field off the screen)
- Every data slot lists its types explicitly with a `default` (HR, Steps, Sunset, Body Battery), and both colour lists mark a default. Never use `allowAny` on a slot: it cannot carry a default, and the editor then fills the slot with its own first choice (Battery) as soon as Data is opened
- Test in the simulator with File → Edit Watch Face (Ctrl+E); Simulation → Complications sets values

## Fonts

Roboto and Roboto Condensed (static hinted TTFs from googlefonts/roboto, Apache 2.0, licence in
`tools/fonts/LICENSE-roboto.txt`; the design's Barlow Condensed and DM Mono files stay there, unused
since 1.0.4) are converted to Connect IQ bitmap fonts (BMFont `.fnt` + `.png`) by
`tools\make-fonts.ps1`, one set per screen size in `resources-round-<W>x<W>/fonts/`. Regenerate after
changing sizes or glyphs. Sizes are the 454 px design sizes × width / 454, with minimums for small
screens; MIP screens get 1-bit hinted glyphs below 20 px. Each font's line box runs from cap top to
the lowest descender, so `TEXT_JUSTIFY_VCENTER` centres the digits (Connect IQ clips ink outside the
line box).

| Font resource | Face | 454 px size (min) | Glyphs |
|---|---|---|---|
| `TimeHeavy` | Roboto Condensed Bold | 156 px | `0123456789` |
| `TimeThin` | Roboto Condensed Regular | 156 px | `0123456789:` (colon centred on the digits) |
| `TimeAod` | Roboto Condensed Light | 156 px | `0123456789:` |
| `Value` | Roboto Condensed Bold | 34 px (16) | digits, `,.:%-/+°`, space, `A–Z a–z` (system data values) |
| `ArcValue` | Roboto Condensed Bold | 32 px (15) | `0123456789%-` |
| `Mono22` | Roboto Regular | 26 px (12) | `A–Z 0–9 -` space |
| `Mono16` | Roboto Regular | 18 px (10) | `A–Z 0–9 ./-%°` space |
| `Mono14` | Roboto Regular | 16 px (10) | `A–Z` space |

The resource names keep their 1.0 meaning (`Mono*` = the small text at its 1.0 size, `TimeThin` =
the minutes); the table gives the current faces and sizes.

Letter-spacing isn't supported by `drawText`, so the tracked labels and date are drawn character by
character (`drawTracked`). All eight fonts together use about 4 KB of app memory on a 218 px watch.
If they fail to load, the view falls back to scalable then system fonts.
On API 4+ `loadResource` hands fonts out as graphics pool references that the watch may purge;
drawing with one it can't bring back is a fatal, uncatchable Invalid Value (fr970, 1.0.1), so
`loadFonts` keeps the resources themselves (`FaceKit.strongResource`) and the ring is drawn from `get()`.

## Implementation notes

- Draw everything procedurally in `ApexFaceView.onUpdate(dc)`; drop the template `layout.xml` label
  and the `Background` drawable's property lookup (ground is always black).
- Cache the static ring (minor + major ticks, arc track) in a `Graphics.BufferedBitmap` created in
  `onLayout`, and rebuild it only when settings change.
- Read sensor data at most once per update; guard every value against `null`.
- Seconds (comet, trail, `SEC` field) exist in high-power mode. AMOLED faces do not get
  `onPartialUpdate` and switch to Always-On; MIP faces keep the comet and trail through
  `onPartialUpdate` (the `SEC` field still shows `--` in low power).
- Keep `onUpdate` cheap: no allocations of large objects per frame.

## Build order

1. Black ground, tick ring, hours/minutes with system fonts, date. Run in the simulator (fr970).
2. Seconds comet + trail; Active ⇄ AOD switching via `onEnterSleep` / `onExitSleep`.
3. Data fields with the metric table and settings.
4. Arc + readout with the arc table and settings.
5. Colour settings (accent, numerals, ink, dim), then Night mode. Done.
6. Custom fonts. Done (`tools\make-fonts.ps1`).
7. Burn-in / memory checks: done with `tools\aod-burnin.ps1` and the simulator's memory readout;
   every field value as `null` is covered by the unit tests.

All seven steps are done.

## Working here

- Build and run with the Monkey C extension ("Monkey C: Run", device fr970), or `monkeyc` from the SDK.
- Tests: `(:test)` functions in `source/*Test.mc` ("Monkey C: Run Tests", or `monkeyc --unit-test` then
  `monkeydo bin\ApexFaceTest.prg fr970 /t` with the simulator open), and
  `powershell -ExecutionPolicy Bypass -File tests\check-resources.ps1` for the resource XML. Keep pure
  logic in `ApexLayout` / `ApexMetrics` (and the shared `FaceCore/kit`: FaceFormat, FaceKit) so it stays testable.
- Per-watch tests: `source/ApexDeviceTest.mc` checks the layout on the screen it runs on (fonts, row
  overlap, time inside the arc, palette, low power). `tools\run-device-tests.ps1` runs the whole
  suite on one watch per screen size, API version and editor config (16 watches, ~25 min, simulator
  open); the resource check fails if a product's screen size or API version isn't in that matrix.
  View tests render at the running watch's own size (`ApexTestUtil.render` / `px`); the view's
  `testProbe` is `(:debug)` so release builds leave it out.
- `manifest.xml` is generated — change products / permissions through the "Monkey C: …" commands.
- Keep the look minimal: if a change adds a colour, a font or a new element, check it against the
  concept above first.
